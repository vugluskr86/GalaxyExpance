# Спецификация формата данных Pixel Shipyard

## 1. Назначение

JSON-файл описывает один сгенерированный корабль и связывает его изображение PNG с игровой геометрией, характеристиками генерации и точками установки оборудования.

Идентификатор текущей версии формата:

```text
pixel-shipyard/v1
```

Рекомендуемое имя файла:

```text
ship_<seed>_<algorithm>.json
```

Соответствующее изображение экспортируется как:

```text
ship_<seed>_<algorithm>.png
```

## 2. Корневой объект

```json
{
  "format": "pixel-shipyard/v1",
  "seed": 1337,
  "algorithm": "ca",
  "palette": "steel",
  "image": {},
  "stats": {},
  "slots": [],
  "parameters": {}
}
```

| Поле | Тип | Обязательное | Назначение |
|---|---|---:|---|
| `format` | string | да | Версия контракта данных. Для этой спецификации строго `pixel-shipyard/v1`. |
| `seed` | integer | да | Seed генератора. Одинаковый seed при одинаковых параметрах должен воспроизводить корабль. |
| `algorithm` | string | да | Алгоритм построения корпуса. |
| `palette` | string | да | Палитра, использованная при рендеринге PNG. |
| `image` | object | да | Геометрия изображения и система координат. |
| `stats` | object | да | Рассчитанные характеристики корабля. |
| `slots` | array | да | Точки и области крепления оборудования. |
| `parameters` | object | да | Полный снимок параметров генератора. |

Неизвестные дополнительные поля должны игнорироваться импортёром, если они не конфликтуют с известными полями.

### 2.1. Поле `raster` — канонический рендер корпуса

Текущий экспортёр всегда добавляет `raster`: массив из `image.gridHeight` строк, каждая длиной `image.gridWidth`. Это точная материализованная маска корпуса в исходной сетке. Она является единственным источником изображения во всех сценах игры и в самом генераторе; PNG остаётся необязательным экспортным файлом для внешнего просмотра.

Допустимые символы: `.` (пустота), `h` (корпус), `a` (акцент), `g` (стекло), `e` (двигатель), `l` (свечение) и `m` (металл). Поле необязательно только для старых v1-файлов: при импорте им строится детерминированный совместимый силуэт, но он не может в точности восстановить исходный корабль. Для точного переноса следует переэкспортировать JSON из текущего генератора.

Параметры визуального шейдинга из `parameters` (палитра, свет, контраст, панели и т. п.) принадлежат экземпляру корпуса вместе с `raster`. Они не берутся из каталога корпуса или из сцены.

## 3. Поле `image`

```json
{
  "gridWidth": 34,
  "gridHeight": 46,
  "scale": 8,
  "crop": true,
  "bounds": {
    "x0": 3,
    "y0": 1,
    "x1": 30,
    "y1": 44
  },
  "background": "dock",
  "origin": "top-left",
  "axis": {
    "x": "right",
    "y": "down"
  },
  "slotCoordinates": "grid-pixels-before-scale"
}
```

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `gridWidth` | integer | `>= 1` | Ширина исходной логической сетки корабля в ячейках. |
| `gridHeight` | integer | `>= 1` | Высота исходной логической сетки корабля в ячейках. |
| `scale` | integer | `>= 1` | Размер одной логической ячейки в пикселях PNG. |
| `crop` | boolean | — | Было ли изображение обрезано по bounding box корабля. |
| `bounds` | object | — | Bounding box непустой части корабля в координатах исходной сетки. |
| `background` | string | — | Режим фона при рендеринге. |
| `origin` | string | `top-left` | Начало координат находится в левом верхнем углу. |
| `axis.x` | string | `right` | Ось X направлена вправо. |
| `axis.y` | string | `down` | Ось Y направлена вниз. |
| `slotCoordinates` | string | `grid-pixels-before-scale` | Координаты слотов заданы в ячейках исходной сетки до масштабирования и кадрирования. |

### 3.1. Bounding box `bounds`

```json
{
  "x0": 3,
  "y0": 1,
  "x1": 30,
  "y1": 44
}
```

Границы включительные:

```text
width  = x1 - x0 + 1
height = y1 - y0 + 1
```

Каждое значение является целым индексом ячейки исходной сетки.

### 3.2. Размер экспортированного PNG

Рендер добавляет по одной служебной ячейке отступа с каждой стороны.

При `crop = true`:

```text
pngWidth  = (bounds.x1 - bounds.x0 + 3) * scale
pngHeight = (bounds.y1 - bounds.y0 + 3) * scale
```

При `crop = false`:

```text
pngWidth  = (gridWidth + 2) * scale
pngHeight = (gridHeight + 2) * scale
```

### 3.3. Перевод координаты слота в координаты PNG

Пусть слот имеет координаты `slot.x`, `slot.y`.

При `crop = true`:

```text
pngX = (slot.x - bounds.x0 + 1) * scale
pngY = (slot.y - bounds.y0 + 1) * scale
```

При `crop = false`:

```text
pngX = (slot.x + 1) * scale
pngY = (slot.y + 1) * scale
```

`pngX` и `pngY` указывают левый верхний угол логической ячейки слота. Центр ячейки в экранных координатах:

```text
centerX = pngX + scale / 2
centerY = pngY + scale / 2
```

## 4. Поле `slots`

`slots` — массив точек крепления. Порядок элементов не должен использоваться как постоянный идентификатор; для ссылок следует применять `id`.

Общая форма:

```json
{
  "id": "engine-0",
  "type": "engine",
  "x": 9,
  "y": 43,
  "rotation": 180,
  "size": {
    "w": 4,
    "h": 2
  },
  "mount": "rear",
  "direction": {
    "x": 0,
    "y": 1
  }
}
```

| Поле | Тип | Обязательное | Назначение |
|---|---|---:|---|
| `id` | string | да | Уникальный идентификатор слота внутри корабля. |
| `type` | string | да | Семантический тип слота. |
| `x` | integer | да | X в исходной сетке. |
| `y` | integer | да | Y в исходной сетке. |
| `rotation` | number | да | Ориентация в градусах по часовой стрелке. Ноль направлен к носу корабля, то есть вверх по изображению. |
| `size` | object | нет | Размер занимаемой или рекомендуемой области в ячейках сетки. |
| `mount` | string | да | Способ или сторона крепления. |
| `direction` | object | нет | Нормализованный дискретный вектор направления. |

Требования:

- `id` должен быть уникален в пределах `slots`.
- `x` находится в диапазоне `0 .. image.gridWidth - 1`.
- `y` находится в диапазоне `0 .. image.gridHeight - 1`.
- `size.w` и `size.h`, когда присутствуют, должны быть положительными целыми числами.
- `direction.x` и `direction.y` в версии v1 принимают значения `-1`, `0` или `1`.
- Слот может не иметь `size` или `direction`; импортёр обязан это поддерживать.

## 5. Типы слотов

### 5.1. `engine`

Точка установки двигателя на корме.

```json
{
  "id": "engine-0",
  "type": "engine",
  "x": 9,
  "y": 43,
  "rotation": 180,
  "size": { "w": 4, "h": 2 },
  "mount": "rear",
  "direction": { "x": 0, "y": 1 }
}
```

Семантика:

- `x`, `y` — центральная точка кормового сегмента двигателя;
- `size.w` — ширина сегмента двигателя;
- `size.h` — глубина окрашенной двигательной секции;
- `direction` направлен к корме и выхлопу;
- `rotation = 180` соответствует направлению вниз.

### 5.2. `weapon`

Точка установки оружия, направленного к носу.

```json
{
  "id": "weapon-0",
  "type": "weapon",
  "x": 2,
  "y": 13,
  "rotation": 0,
  "size": { "w": 1, "h": 5 },
  "mount": "left",
  "direction": { "x": 0, "y": -1 }
}
```

Семантика:

- `x`, `y` — верхняя ячейка области оружия;
- `size.h` — длина ствола или монтажной области;
- `mount` принимает `left` или `right`;
- `direction` направлен к носу;
- `rotation = 0` соответствует направлению вверх.

### 5.3. `cockpit`

Область кабины или командного модуля.

```json
{
  "id": "cockpit-0",
  "type": "cockpit",
  "x": 17,
  "y": 8,
  "rotation": 0,
  "size": { "w": 7, "h": 3 },
  "mount": "internal"
}
```

Семантика:

- `x`, `y` — приблизительный центр кабины;
- `size` — bounding size процедурно созданной эллиптической области;
- `mount = internal` означает встроенный модуль;
- `direction` отсутствует, поскольку кабина не задаёт вектор действия.

### 5.4. `utility`

Универсальная точка для игрового оборудования, центра масс, эффекта выбора или служебной привязки.

```json
{
  "id": "center-0",
  "type": "utility",
  "x": 17,
  "y": 23,
  "rotation": 0,
  "mount": "center"
}
```

Семантика:

- точка вычисляется как центр bounding box корабля;
- `size` отсутствует;
- `direction` отсутствует;
- в v1 всегда создаётся один слот `center-0`.

## 6. Поле `stats`

Пример:

```json
{
  "len": 44,
  "beam": 28,
  "hull": 412,
  "glass": 15,
  "acc": 39,
  "mass": 173.0,
  "engines": 4,
  "guns": 2,
  "cls": "фрегат",
  "ratio": 1.57,
  "fill": 33,
  "twr": 3.24
}
```

| Поле | Тип | Единица/семантика |
|---|---|---|
| `len` | integer | Длина bounding box корпуса в ячейках. |
| `beam` | integer | Ширина bounding box корпуса в ячейках. |
| `hull` | integer | Число твёрдых ячеек, включая корпусные материалы и оснащение, но без свечения двигателя. |
| `glass` | integer | Число ячеек материала кабины/стекла. |
| `acc` | integer | Число акцентных и металлических ячеек. |
| `mass` | number | Условная масса: `hull * 0.42`, округлённая до 0.1. |
| `engines` | integer | Количество слотов типа `engine`. |
| `guns` | integer | Количество слотов типа `weapon`. |
| `cls` | string | Класс по числу твёрдых ячеек. |
| `ratio` | number | Отношение `len / beam`, округлённое до 0.01. |
| `fill` | integer | Процент заполнения bounding box твёрдыми ячейками. |
| `twr` | number | Условная тяговооружённость: `engines * 140 / mass`, округлённая до 0.01. |

Классификация `cls` в версии v1:

| Условие по `hull` | Значение |
|---|---|
| `< 90` | `перехватчик` |
| `< 220` | `корвет` |
| `< 430` | `фрегат` |
| `< 800` | `крейсер` |
| `>= 800` | `капитальный` |

Для пустого результата генератор может вернуть сокращённый объект статистики без `glass`, `acc` и `twr`; импортёру рекомендуется считать отсутствующие числовые поля равными нулю.

## 7. Поле `parameters`

`parameters` содержит полный снимок состояния генератора на момент экспорта. Состав полей зависит от версии приложения и включает параметры формы, алгоритма, очистки, оснащения, освещения, палитры и вывода.

Пример фрагмента:

```json
{
  "algo": "ca",
  "w": 34,
  "h": 46,
  "symmetry": "vertical",
  "seed": 1337,
  "beam": 0.85,
  "ftCockpit": true,
  "ftEngines": true,
  "scale": 8,
  "crop": true
}
```

Правила совместимости:

- игровой импортёр не должен требовать конкретного полного набора `parameters`;
- неизвестные параметры следует игнорировать;
- для игрового размещения оборудования источником истины являются `image` и `slots`, а не параметры генератора;
- `seed`, `algorithm` и `palette` на верхнем уровне дублируют наиболее важные параметры для быстрого доступа.

## 10. Рекомендации для игрового импортёра

1. Проверить `format` до чтения остальных данных.
2. Использовать `raster` и параметры рендера из JSON как источник изображения; PNG не должен подменять корпус в игре.
3. Использовать `image.scale`, `image.crop` и `image.bounds` для перевода слотов в координаты PNG, если PNG нужен внешнему потребителю.
4. Хранить привязки оборудования по `slot.id`, а не по индексу массива.
5. Не считать `size` обязательным.
6. Игнорировать неизвестные поля и неизвестные значения `mount`.
7. При физике или коллизиях не использовать PNG как единственный источник геометрии; для визуала доступна `raster`, но физическая маска и коллизии пока имеют отдельный контракт.

## 11. Ограничения версии v1

- JSON старого образца может не содержать пиксельную маску корпуса; текущий экспорт всегда содержит `raster`. Полигон коллизии по-прежнему не экспортируется.
- Нет отдельного идентификатора экземпляра корабля помимо `seed` и параметров.
- Не указаны якорь спрайта, pivot и физический центр масс.
- `rotation` и `direction` частично дублируют друг друга.
- `parameters` не имеет отдельной строгой схемы и может расширяться.
- Экспорт «PNG + данные» создаёт два отдельных файла, а не архив.

Эти ограничения можно устранить в `pixel-shipyard/v2`, не меняя семантику полей v1.
